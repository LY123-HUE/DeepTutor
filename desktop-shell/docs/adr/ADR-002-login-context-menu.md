# ADR-002: 账号菜单的交互方式与实现通道

## Status

**Accepted** — v2（2026-09-16 修订）：由 v1 的**全窗口右键弹出**改为
**左下角账号按钮点击切换的下拉菜单**，**不再劫持右键**（页面原生右键原样保留）。

- 决策者：EduBuddy 桌面端
- 相关：`docs/engineering-setup-plan.md` §3、`desktop/inject.py`

---

## Context

计划 §3.4 有一个待定项：账号菜单以什么方式出现、多大范围生效。

| 方案 | 描述 | 取舍 |
| --- | --- | --- |
| ①（v1 已实现） | 整个窗口任意处右键都弹 | Tokengine 操作统一收口；但**劫持全局 contextmenu**，可能挡掉页面自带的复制/粘贴右键 |
| ②（当前） | 登录后点账号按钮弹下拉，再点收起 | 不劫持右键、入口明确、符合桌面端常见「账号菜单」习惯 |

DeepTutor 的聊天区里**右键复制**是高频操作，v1 全量劫持即便加了可编辑区豁免
仍然覆盖空白区，与用户预期不符。用户最终确认：**不做右键菜单**，改成点击切换。

## Decision

v2 采用方案②——**点击切换的下拉菜单**：

- **触发**：左下角「登录/账号」按钮。未登录时点击 → 发起 OAuth 登录；
  已登录/已配置时点击 → 在按钮上方弹出账号下拉菜单；**再点一次收起**。
- **不劫持右键**：整个页面保留浏览器原生右键菜单（复制/粘贴等原样可用）。
- **通道**：复用已验证的「隐藏 input 事件槽 + Python `evaluate_js` 轮询」
  （与登录按钮同一套机制，`desktop/inject.py`），不依赖可能失效的 `js_api` 桥。
- **菜单渲染**：页面侧自绘，浅色主题（白底、圆角、细描边、hover 高亮）；
  按钮点击切换开/关；Esc / 点菜单外 / 滚动 / 滚轮 / 失焦 → 关闭。
- **数据流**：Python 每轮 ensure 把按登录态构建的菜单模型推回页面
  （`window.__edubuddyMenuUpdate(<json>)`，含 `logged_in`/`configured` 标志，
  页面据此决定按钮点击路由）；点击菜单项写 `menu:<action>:<ts>` → Python 分发。
- **危险项**：退出登录需要「再次点击」二次确认（自绘，不用原生 confirm）。
- **复制 API 地址**：只复制 `relay_base`，**不提供复制业务 token**（避免泄露）。

## Consequences

**更容易的**：
- 不再干扰页面任何右键操作（复制/粘贴/检查元素原样保留）。
- 触发入口明确（账号按钮），发现成本低；点击即见、再点即隐，符合直觉。
- 登录、刷新模型、切换账号、退出登录、打开平台、复制地址、关于——操作集中在一处。
- 登录后/未登录自动切换两套菜单；退出后按钮自动回到「登录」并被摘除 catalog。

**更困难的 / 需要留意**：
- 菜单入口收敛到单个按钮：若按钮被页面元素遮挡或用户未注意到，需靠标题/title 提示。
- 下拉定位锚定按钮上方（右缘对齐），窗口过小时可能贴边——已做边界 clamp（8px 安全边距）。
- 菜单模型是 Python 推过去的一份「快照」：若页面想要子菜单/动态加载，当前模型需扩展。
